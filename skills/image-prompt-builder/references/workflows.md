# 按任务选用

下列框架供助手内部整理；输出时填入已知信息并删去无关字段，不让用户逐项填表。

## 从零生图

顺序可按请求调整：用途和第一视觉重点 → 主体与动作 → 布局与留白 → 可见风格细节 → 准确文案与位置 → 限制。简单任务几句话即可，不堆叠通用美学形容词。

无需文字时明确“不含文字”，不要让模型把“无”画成文字。指定文案放在引号内，保留拼写、大小写和标点；明确只出现要求的文字。未提供统计数据、品牌口号或功能时不要编造。

## 局部改图

明确底图，以及“将哪个对象的哪种属性改成什么”。按原图列出具体保护内容；融合不得跨入保护区。先读取 [边界与验收规则](local-edit-safety.md)。若只改杯身颜色，不顺带换背景或添加新杯子。

自拟示例：

```text
编辑上传的原图，将桌上红色杯子的杯身改为蓝色。
保留杯子的外形、白色竖条图案、位置和大小。
保留桌上的黄色书本以及背景中的圆形装饰。
保留原图构图，仅允许杯身换色所需的局部明暗变化。
```

此例的物体细节只有在输入确实具备时才可使用，不是所有图片的默认描述。

## 草图转图

分开说明结构与表现：已画出的对象、数量、布局和观察方向属于结构；材质和照明属于可补全表现。箭头、框线、手写标注按用户意图作为说明，通常不绘入成品。不能读清的关键结构需确认，不用想象代替观察。

## 多图参考

先确定底图。分别写出其他图提供什么、哪些元素应进入底图以及放在哪里。风格参考不自动等于复制其人物和文字。没有必要不要求增加参考图。

## 多轮修正

引用最近认可的具体图片。本轮只处理当前问题，并重复需要保留的已经满意的部分。如果用户说“换背景再换衣服”，安排两步并保留两项要求，而不是把第二项省略。

## 冲突和不足

- 低风险缺项：用清楚、简洁、自然等与任务一致的执行要求补全，可简短告知假设。
- 核心冲突：例如同一杯身必须同时完全红色和完全蓝色，只问用户保留哪个目标，不产出互相矛盾的最终指令。
- 缺图片：可先写不依赖图片细节的通用指令；涉及身份判断、指定局部位置或多图分工且无法合理推断时，先请求所缺输入。
- 只要提示词：直接交付代码块，不夹带问卷、过程说明和自评分。
