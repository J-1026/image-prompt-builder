# v1.0.1 局部编辑修订验证

日期：2026-09-10。

## 已知失败与本次修正

真实使用中，助手把“更有压迫感的视角”错误扩展为允许重构背景，并主动在提示词中放开沙丘透视与地面阴影，生成后又未把背景变化判为失败。说明提示词完整性检查不能代替局部编辑的保留验收。

v1.0.1 收紧的是局部编辑时的范围继承、冲突处理、底图选择和交付验收；并未禁止用户明确授权的整体重绘。新增可选像素工具负责确定性合成和保护区域检查，普通提示词功能不依赖它。

## 结构验证

Codex `quick_validate.py` 返回 `Skill is valid!`。结构检查不证明所有运行行为都正确。

## 三个独立上下文试用场景

执行助手只读取新版 Skill、必要参考及三个请求，在一个独立上下文中顺序回答，不读取本报告或原对话。制作者随后检查实际输出；没有声称预注册评分或第三方认证。

| 场景 | 观察结果 |
| --- | --- |
| 锁定沙纹与人物，只换飞船并增强压迫感，尚无图片 | 输出保留镜头、沙纹、人物与原投影，仅改舰体透视和体量；明确未看图及严格保留的执行条件 |
| 用户明确允许整体鸟瞰重构 | 按新授权重排沙漠与人物，保留服装和主题，未强行沿用旧背景锁定 |
| 用户报告杯子换色成功但书本移动，缺少原图 | 根据用户描述判定保留失败，说明未亲自核验，并要求回到正确底图 |

原始请求与完整输出：[v1.0.1-scope-responses.json](../tests/results/v1.0.1-scope-responses.json)。三个结果符合本次修正方向，不能外推为所有任务零失败。

## 像素脚本验证

使用 Pillow，运行 `python3 -m unittest discover -s tests -p test_protected_region.py -v`，7项全部通过：

- 发现保护区的真实像素变化，审计返回失败状态。
- 合成后保护区等于原图，同时可编辑区保留候选修改，过渡区正确混合。
- RGBA透明度变化纳入检查，不只检查RGB。
- 拒绝尺寸不一致，避免暗中缩放。
- 拒绝没有白色保护像素的空保护蒙版。
- 拒绝覆盖原文件。
- 拒绝不一致的ICC色彩配置。

源测试：[test_protected_region.py](../tests/test_protected_region.py)。工具逐像素一致只针对蒙版白色区域。错误选择蒙版、遗漏人物、边缘接缝或船型不正确都需要另行验收，不能由像素报告排除。

## 限制

本次未重新运行全部v1.0.0行为场景，未测跨宿主自动发现或不同图像模型，不提供画质提升或节省时间的百分比。图片生成、区域合成和区域审计是三个不同步骤；不能把合成后的保护区不变宣传为模型仅凭提示词就能精确锁定。
