# Image Prompt Builder · 图像提示词助手

**说一句你想要的效果，有原图就上传。Skill 自动补全、理顺和校正，给出可直接用的提示词。**

适用于生图、局部改图、草图转图、多张参考图和后续修改。无需自己填写长表格；只在关键要求矛盾或必要素材缺失时简短询问。

这是独立制作的 Skill，依据 OpenAI 的图像提示词指南整理，并非 OpenAI 官方出品。当前版本负责提示词，不内置生图服务，不需要提供 API Key。实际生图由你选用的工具完成，其账号和额度另行要求。

**实际图片案例：[8 张图片，两个完整使用路径](docs/GALLERY.md)**——宇航员参考与猴子香蕉多轮修改；酒瓶实拍、产品图与人物场景。附图片顺序、Skill 作用和可复用指令。

**提示词示例：[两个完整使用示例](docs/EXAMPLES.md)**——做教程封面、给杯子换颜色。展示用户原话、当次完整输出、自动补充项和下一步操作；改图例子附可下载的输入图。

## 安装与开始

下载 [最新版本](https://github.com/J-1026/image-prompt-builder/releases/latest) 中的 `image-prompt-builder-v1.0.1.zip`。解压后得到 `image-prompt-builder` 文件夹，内部第一层应直接包含 `SKILL.md`。

**Codex 手动安装：**把解压得到的整个 `image-prompt-builder` 文件夹放进用户目录的 `.agents/skills/`。最终路径应当是：

- macOS / Linux：`~/.agents/skills/image-prompt-builder/SKILL.md`
- Windows：`%USERPROFILE%\.agents\skills\image-prompt-builder\SKILL.md`

不要把外层仓库文件夹套进去，也不要只复制单个 `SKILL.md`，它需要同目录里的 `references/`。

也可以在 Codex 中对内置安装助手说：

```text
$skill-installer 从 https://github.com/J-1026/image-prompt-builder 安装 skills/image-prompt-builder 这个 Skill。
```

Codex 安装位置与发现方式依据 [官方技能文档](https://learn.chatgpt.com/docs/build-skills)。其他支持 Agent Skills 的工具须按各自目录要求安装；本项目没有宣称在所有工具中都已实测。

安装成功后，可以明确调用：

```text
$image-prompt-builder 帮我写一段改图提示词：把照片背景换成咖啡馆，人物保持原来的样子。
```

Codex 会发现技能变更；若新增 Skill 没出现，重启 Codex 后再调用。名称已出现在技能列表中，才表示你的工具完成了发现；仅下载 ZIP 不代表已经安装。

## 使用指南

### 1. 说需求，有图就上传

```text
把桌上这个红色杯子改成蓝色，其他东西别动。帮我写提示词。
```

你无需再填写用途、构图、风格等表格。助手会读取可访问的原图，把必要信息补进提示词；不会假装看过没有上传的图片。

### 2. 复制生成的提示词

以[完整示例中的输入图](docs/EXAMPLES.md)为例，下面是便于阅读的简版；该页保留当次完整输出：

```text
编辑上传的原图，将桌上红色杯子的红色杯身和杯柄改为蓝色。
保留杯子的外形、白色竖条图案、位置和大小。
保留桌上的黄色书本以及背景中的圆形装饰。
保留原图构图，仅允许换色所需的边缘融合。
```

助手还会给出本次验收要求，例如颜色是否正确、杯身图案是否保留、周围物体是否保留。

### 3. 在生图工具中使用

将提示词和同一张原图一起交给你使用的图像工具。仅复制文字、未上传原图，无法完成针对该图的可靠编辑。这个版本不会自动完成这一步。

### 4. 不满意就反馈具体问题

将原图和生成结果一起发给助手：

```text
蓝色已经对了，但杯子上的图案被改掉了。帮我写下一轮修改指令。
```

它会围绕这个问题给下一轮提示词，保留已经满意的部分。如果要求无法兼容，它会解释矛盾并询问关键取舍。

## 其他调用例子

```text
$image-prompt-builder 写一段小红书封面提示词，标题逐字使用“AI修图小技巧”，清楚好读，不要其他文字。给我两个布局方向。
```

```text
$image-prompt-builder 把这张书房草图整理成写实效果图的提示词，家具位置按草图，手写标注不要出现在成品里。
```

```text
$image-prompt-builder 图1是底图，图2只参考配色，保留图1的人物和文字。
```

## 如何量化效果

### v1.0.1：局部修改的保护边界

“换飞船，要更有压迫感”不会自动变成“允许重画沙丘、移动人物”。Skill 会沿用已经确认的保留要求，把具体沙纹、轮廓和位置列为保护内容。局部效果与保护边界冲突时，先选择只改对象的方案；确实无法兼容才询问取舍。用户明确授权整体重绘时，不强行锁定旧布局。

实际执行改图后，改动目标与保护项分别检查。背景被改，即使飞船好看，也不能当作局部编辑成功。下一轮回到正确底图修复，不把失败结果自动当成新基准。

严格保留不能单靠提示词：新版提供可选的保护区域合成与审计脚本。宿主已有合成授权、能正确选择保护蒙版且安装 Pillow 时，可把保护区域从原图原样复制，再检查像素；不具备这些条件时不能声称已锁定像素。蒙版覆盖是否正确、边缘是否自然、新对象是否达标仍需单独验收。普通提示词功能没有新增依赖。

详细用法见 [局部编辑边界与验收](skills/image-prompt-builder/references/local-edit-safety.md)。

每个任务先列可检查的目标与保留项，再看结果。

| 指标 | 定义 |
| --- | --- |
| 提示词要求覆盖率 | 已覆盖的用户明确要求数 ÷ 总要求数；这不是图像成功率 |
| 首轮图像可用率 | 首次出图同时通过全部关键要求的任务数 ÷ 实际出图任务数 |
| 返工轮数 | 首次出图后，达到验收要求追加的修改次数 |
| 保留项通过率 | 实际图片中确认保留正确的项目数 ÷ 可判断的保留项目数；另列无法判断项 |
| 总用时 | 从开始描述到认可结果的真实计时，包含整理提示词及返工 |

对照测试应保持输入图片、任务、图像模型和设置一致，重复测试并保留失败样例。不能用检查提示词的分数推断画质提升。

v1.0.1 的新增检查见 [局部编辑修订验证](docs/VALIDATION-v1.0.1.md)，历史检查见 [v1.0.0 验证报告](docs/VALIDATION.md)。报告不填造不存在的图片、耗时、通过率或提升比例。
